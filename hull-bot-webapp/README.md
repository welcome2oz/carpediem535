# Hull Suite 봇 콘솔 (HTML 한 파일)

Hull Suite 자동매매 봇(hullbot v2, ①+C+D, 바이비트)의 현황·기록·로그·설정을 브라우저 한 화면에서 보는 **HTML 파일 하나**입니다.
서버·설치·파이썬이 필요 없고 더블클릭으로 엽니다. 봇 코드는 건드리지 않고, 봇이 남기는 파일만 읽습니다.

## 사용 방법

1. `hull-bot-console.html`을 아무 곳에나 저장합니다(hullbot 폴더 안도 괜찮음).
2. **크롬 또는 엣지**로 엽니다.
3. **봇 폴더 선택** → `bot.py`가 있는 `hullbot` 폴더 → "파일 수정 허용"을 묻으면 허용.
4. 다음부터는 **다시 연결** 버튼만 누르면 됩니다(브라우저 보안상 열 때마다 한 번 클릭).

## 내장 설명서

HTML 안에 설명서가 들어 있습니다. 처음 열면 펼쳐져 있고, 폴더를 연결한 뒤에는 오른쪽 위 **📖 설명서** 버튼으로 엽니다.
내용: 이 화면과 봇의 관계, 키 없이 모의 운용 시작하기(4단계), 운영 현황 카드 읽는 법, 자주 하는 일,
데모·실계정 전환(API 키는 본인이 .env에 직접), 설정 항목 표, 문제 해결. 모든 내용은 봇의 README_ko.md와 bot.py 기준입니다.

## 화면

| 영역 | 내용 | 읽는 파일 (bot.py 기준) |
|---|---|---|
| 실행 여부 | 봇은 매 확인 주기(`loop_sec`, 기본 60초)마다 상태 파일을 저장하므로, 저장 시각이 `loop_sec`×3(최소 3분) 안이면 "실행 중" | `state_<모드>.json` 수정 시각 |
| 포지션 | 심볼별 보유/없음/진입 처리 중, 수량(현물 + 선물), 평균 진입가, 손절가, 원금, 누적 펀딩. 손절 주문이 아직 확인되지 않았으면(`stop_ok=false`) 경고 | `state_<모드>.json`의 `sym` |
| ① 재진입 | 이번 상승 신호에서 손절 횟수, 제한에 걸리면 "재진입 제한: 하락 후 새 상승 신호 대기" | `state_<모드>.json`의 `swing` |
| 신호·손익 | 마지막 일일 신호(상승/하락, 한국 시각), 실현손익 합계와 횟수, 최근 "진입 안 함" 사유(펀딩 과열·재진입 제한) | `journal_<모드>.csv` |
| 모의 계좌 | USDT 잔고 | `paper_account.json` |
| 신규 진입 멈춤 | 스위치로 `STOP` 파일 생성/삭제 (보유 포지션 손절 관리는 계속) | `STOP` |
| 매매 기록 | 한국 시각, 이벤트 색 구분, 숫자 정리. 심볼·이벤트(매매만/전체/일일 신호/손절가) 필터, 검색, 실현손익 합계 | `journal_<모드>.csv` |
| 봇 로그 | 마지막 300줄, 경고·오류 색 표시 | `logs/bot_<모드>.log` |
| 상태 파일 | 원본 JSON | `state_<모드>.json`, `paper_account.json` |
| 설정 | `config.json` 편집. 저장 전에 bot.py가 시작할 때 요구하는 값을 검사(mode, symbols, leverage 10 이하, stop_pct, capital_mode와 심볼별 fixed_usdt/weights, spot_half는 fixed에서만, max_reentry 정수 또는 null 등)하고 이전 파일은 `config.json.bak`으로 보관 | `config.json` |

15초마다 자동 갱신됩니다. 휴대폰 폭에서도 깨지지 않지만, 폴더 접근은 PC의 크롬/엣지에서만 됩니다.

## 할 수 없는 것

- **봇 시작·정지, 신호 확인은 bat 파일로** 합니다(웹페이지는 PC의 프로그램을 실행할 수 없음).
  각 모드 카드에 실행 파일(`run_paper.bat` 등)이 적혀 있고, 오늘 신호와 "지금 진입한다면" 수량·손절가는 `check_signal.bat`입니다.
- 설정을 바꾸면 **실행 중인 봇은 다시 시작해야** 반영됩니다(봇은 시작할 때 한 번 읽음). bat 파일의 `--mode`가 config의 `mode`보다 우선합니다.
- 화면의 가격·손익은 봇이 마지막으로 기록한 값입니다. 실시간 시세나 미실현 손익은 바이비트 화면에서 확인하세요.
- 파이어폭스·사파리는 폴더 접근 기능이 없어 동작하지 않습니다.

## 보안

- 외부 통신 코드가 없어 파일이 이 PC 밖으로 나가지 않습니다. `.env`는 읽지 않습니다.
- 쓰는 파일은 `STOP`, `config.json`, `config.json.bak`뿐입니다.
- 기록 파일을 엑셀로 열어 두면 읽지 못할 수 있습니다. 엑셀을 닫고 새로고침하세요(봇은 그동안에도 매매를 계속하고 로그에만 남깁니다).

## 점검

```bash
node test_console.mjs   # playwright 필요
```

`fixtures/`는 **봇 자신의 코드로 만든 파일**입니다.
- `journal_testnet.csv`, `state_testnet.json`: 봇의 `tests/test_live_mock.py`(가짜 바이비트 서버)가 쓴 파일입니다. 진입 → 한쪽 다리 손절 → 재진입 → 두 번째 손절 → 재진입 제한 흐름이 담겨 있습니다.
- `journal_paper.csv`, `state_paper.json`, `paper_account.json`, `logs/bot_paper.log`: 봇의 PaperBroker로 진입한 뒤 펀딩 정산까지 진행한, 두 다리를 보유 중인 상태입니다. `test_paper.py`의 가짜 시세를 썼습니다.

점검 항목(Chromium 141에서 통과):
- 실행 여부, 보유 포지션, 재진입 제한, 실현손익 합계(−84.82 USDT, 2회) 표시
- UTC를 한국 시각으로 변환, 기록 필터 4종
- 로그·상태 파일 표시, `.env` 비노출
- STOP 파일 생성/삭제
- 설정 검사(잘못된 값 8종 거부, 올바른 값 저장 + 백업)
- 설명서: 연결 전 펼침, 연결 후 접힘, 버튼으로 열고 닫기
