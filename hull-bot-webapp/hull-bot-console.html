이 화면은 무엇인가요?

자동매매는 봇(hullbot 폴더의 bot.py)이 합니다. 이 화면은 봇이 남긴 기록을 읽어서 보여 주는 계기판입니다. 이 화면은 바이비트에 연결하지 않고, 주문을 내지 않으며, API 키도 쓰지 않습니다.

→

④ 이 화면이 파일을 읽어 표시포지션·신호·손익·로그
API 키가 없어도 모의(paper) 모드와 신호 확인은 바로 해 볼 수 있습니다. 실제 돈은 쓰이지 않습니다.
처음 시작하기 — 키 없이 모의 운용 (약 10분)

준비물: 윈도우 PC, 파이썬(Python), 압축을 푼 hullbot 폴더, 크롬 또는 엣지

1
오늘 신호 확인
hullbot 폴더에서 check_signal.bat을 더블클릭합니다. 검은 창에 BTC·ETH별로 다음이 나옵니다.
  • 신호 long(상승) 또는 exit(하락): 상승이면 봇이 매수하고, 하락이면 보유분을 팝니다.
  • 펀딩비 최근 7일 평균: "과열"이면 그날은 새로 사지 않습니다.
  • "지금 진입한다면": 원금 1,000 USDT로 살 수량과 손절가 예시입니다.
주문은 나가지 않습니다. 아무 키나 누르면 창이 닫힙니다.
"'python'은(는) 내부 또는 외부 명령… 이 아닙니다"가 나오면 파이썬이 설치되지 않은 것입니다. python.org에서 설치하고, 설치 첫 화면의 "Add python.exe to PATH"를 꼭 체크하세요.
2
모의 운용 시작
run_paper.bat을 더블클릭합니다. 검은 창이 열리고 "시작: 모드 paper…"가 보이면 정상입니다.
  • 실제 주문 없이 바이비트 공개 시세로 가상 계좌(시작 잔고 2,100 USDT)를 운용합니다.
  • 검은 창을 닫으면 봇도 멈춥니다. 켜 둔 채로 두세요. PC 절전 모드도 꺼 두세요.
  • 매매 판단은 매일 한국 시각 09:02에 하루 한 번입니다. 켜자마자 매수하지 않는 것이 정상입니다.
3
이 화면에 봇 폴더 연결
아래 「봇 폴더 선택」 → hullbot 폴더 선택 → 브라우저가 "파일 보기/수정 허용"을 물으면 허용.
연결되면 「운영 현황」의 모의 paper 카드에 초록 점과 "실행 중"이 보입니다. 다음부터 이 HTML을 열면 「다시 연결」 버튼만 누르면 됩니다.
4
매일 확인
09:02 이후 이 화면을 열어 카드의 신호, 보유 여부, 손절가를 봅니다. 자세한 내역은 아래 「매매 기록」 탭에 있습니다.
바로 진입하는 모습을 보고 싶으면 hullbot 폴더 주소창에 cmd를 입력하고 Enter를 눌러 명령창을 연 뒤 python bot.py --mode paper --decide-now를 입력하세요. 지금 신호로 한 번 판단하고 끝납니다(모의·데모·테스트넷만 가능).

손절 주문 확인 안 됨거래소에 손절 주문이 아직 걸리지 않았습니다. 봇이 1분마다 다시 시도하고, 그동안 봇이 직접 가격을 감시합니다.
재진입 제한같은 상승 신호 안에서 손절을 두 번 당했습니다. 신호가 하락으로 바뀌었다가 다시 상승할 때까지 사지 않습니다(규칙 ①).
진입 안 함: …상승 신호인데도 사지 않은 이유입니다(펀딩비 과열, 재진입 제한, STOP 파일 등).
실현손익팔아서 확정된 손익의 합계입니다(수수료·펀딩 포함). 보유 중인 포지션의 평가손익은 포함되지 않습니다.
자주 하는 일
하고 싶은 것방법
새로 사지 않게 잠시 멈추기「운영 현황」 오른쪽 위의 신규 진입 멈춤 (STOP)을 체크합니다. 보유 중인 포지션의 손절 관리는 계속됩니다. 체크를 풀면 다시 삽니다.
봇 끄기봇의 검은 창을 클릭하고 Ctrl+C를 누릅니다. 보유 포지션과 거래소에 걸어 둔 손절 주문은 그대로 남습니다. 다시 켜면 이어서 관리합니다.
원금(투자 금액) 바꾸기「설정」 탭에서 fixed_usdt의 숫자를 바꾸고 「저장」을 누른 뒤, 봇을 껐다 켭니다(봇은 켤 때만 설정을 읽음).
지난 매매 보기「매매 기록」 탭에서 모드를 고릅니다. 심볼·이벤트 필터와 검색을 쓸 수 있고, 위쪽에 실현손익 합계가 나옵니다.
오류 확인「봇 로그」 탭에서 빨간색(ERROR)·주황색(WARNING) 줄을 봅니다.
PC를 껐을 때거래소에 걸린 손절 주문은 계속 작동합니다. 하지만 매일 신호 판단, 손절가 갱신, 봇 감시는 멈춥니다. 다시 켜면 bat 파일을 다시 실행하세요.
모의 다음 단계 — 데모 트레이딩, 실계정 (API 키 필요)
API 키는 저(Claude)를 포함해 누구에게도 보내지 마세요. 키는 hullbot 폴더의 .env 파일에 본인이 직접 붙여넣습니다. 이 화면은 .env를 읽지 않습니다. 키가 없으면 봇은 데모·실계정 모드를 시작하지 않고 ".env 파일에 … API_KEY / … API_SECRET 을 넣어 주세요"라고 알리며 멈춥니다.
A
데모 트레이딩 (실제 시세 + 가상 자금, 실계정 전에 꼭)
  1. bybit.com에 로그인하고 데모 트레이딩으로 전환한 뒤 API 키를 만듭니다. 권한은 계약(Contract) 주문·포지션 + 현물(Spot) 거래만 켜고, 출금·이체는 끕니다.
  2. 데모 계정의 통합거래계정 담보(Collateral) 설정에서 BTC·ETH를 켭니다. 포지션 모드는 단방향(One-Way)으로 둡니다.
  3. .env.example을 복사해 이름을 .env로 바꾸고, BYBIT_DEMO_API_KEY, BYBIT_DEMO_API_SECRET에 붙여넣습니다.
  4. 명령창에서 python bot.py --mode demo --decide-now를 실행해 한 번 진입해 봅니다. 바이비트 화면에서 현물 보유, 선물 포지션(원금의 약 1배), 선물 손절가, 현물 '조건부 주문'의 매도 주문을 확인하세요.
  5. 문제가 없으면 run_demo.bat으로 며칠 돌려 이 화면의 데모 demo 카드에서 손절가 갱신과 기록을 확인합니다.
B
실계정 (실제 돈)
  1. 봇 전용 서브계정을 만듭니다. 다른 코인이 섞이면 봇이 현물 보유를 잘못 판단합니다.
  2. 서브계정에 USDT를 원금 합계 + 약 5% 넣습니다(기본 설정이면 2,000 + 100).
  3. 담보 설정, 단방향 모드, API 키 권한을 데모와 똑같이 맞춥니다. 키에는 IP 제한을 거는 것을 권장합니다.
  4. .env의 BYBIT_API_KEY, BYBIT_API_SECRET에 직접 입력하고 run_live.bat을 실행합니다. LIVE를 입력해야 시작됩니다.
  5. 처음에는 작은 원금으로 시작하고, 기록을 확인한 뒤 늘리세요.

투자 조언이 아닙니다. 봇은 과거 자료로 검증한 규칙을 실행할 뿐 수익을 보장하지 않습니다. 실제 손절 손실은 수수료와 체결 미끄러짐 때문에 원금의 약 5.15% 이상이고, 급락·갭이면 더 큽니다(봇 README 6절).

운영 현황

"실행 중"은 봇이 매 확인 주기(loop_sec)마다 저장하는 state 파일의 저장 시각으로 판단합니다. 시작·정지는 bat 파일로 합니다(브라우저는 프로그램을 실행할 수 없음). 정지는 봇 창에서 Ctrl+C — 보유 포지션과 거래소 손절 주문은 남습니다. 오늘 신호와 "지금 진입한다면" 수량·손절가는 check_signal.bat.
